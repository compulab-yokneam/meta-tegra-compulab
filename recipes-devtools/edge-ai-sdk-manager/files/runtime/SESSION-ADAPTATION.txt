Ubuntu preview session adaptation
================================

The adapted launchers do not create a weston user or compositor. They keep
the original physical-port/compact-index mapping, simultaneous Argus view,
IMX676/IMX678 mode presets, GStreamer recording/JPEG and fullscreen options.

Preferred preview: run from a terminal inside the logged-in Ubuntu user's
X11 or Wayland desktop. gst_camera.sh live --display-backend auto selects
the current session: nv3dsink for X11, waylandsink for Wayland. Override
with --display-backend x11 or --display-backend wayland when needed.
The GTK Argus application uses X11/XWayland and therefore needs DISPLAY
and the desktop session's normal Xauthority access.

SSH/serial preview as the desktop user: the GStreamer launcher can obtain
missing display variables from that user's systemctl --user environment.
Only DISPLAY, XAUTHORITY, WAYLAND_DISPLAY and XDG_SESSION_TYPE are parsed,
as literal data, without shell evaluation. No UID, account, display number
or Xauthority path is guessed. If the user manager has no desktop metadata,
provide the actual DISPLAY/XAUTHORITY or WAYLAND_DISPLAY explicitly.

Example, from a terminal belonging to the logged-in desktop user:
  /opt/compulab/bin/gst_camera.sh live --sensor-id 0
  /opt/compulab/bin/gst_camera.sh live --sensor-id 0 --fullscreen

Wayland fullscreen uses waylandsink's fullscreen property. X11 fullscreen
uses /usr/libexec/edge-ai-gst-x11-preview: a GTK3 window with a native video
overlay and a real fullscreen request, not a guessed screen-sized window.
It embeds ximagesink with videoscale to preserve the video aspect ratio
while filling the fullscreen window; windowed X11 uses standalone nv3dsink.
Escape, closing the window or Ctrl+C stops the preview. This helper needs
the Python GTK/GStreamer bindings listed in DEPENDENCIES.txt; SDK runtime
provisioning installs these dependencies.

Root preview: explicitly provide EDGE_AI_DESKTOP_USER. For GTK also
provide EDGE_AI_DISPLAY and EDGE_AI_XAUTHORITY from that user's session.
Do not guess DISPLAY=:0 or assume a fixed UID. For GStreamer an explicit
EDGE_AI_WAYLAND_DISPLAY may disambiguate multiple sockets. The helper
requires a real non-root account and existing /run/user/UID, delegates
through runuser and never evaluates arguments as shell code. GStreamer
auto mode discovers the selected user's session after delegation; explicit
X11 mode requires EDGE_AI_DISPLAY and EDGE_AI_XAUTHORITY as above.

No helper reads /proc/*/environ, opens credentials, creates an account,
changes display permissions or uses xhost. X11 socket/session metadata
must be configured by the administrator from the intended desktop session.

Capture/record do not need a display or this helper. All operations still
need functioning camera drivers, matching DT/NITO and NVIDIA userspace.
Offline tests cover display selection, literal argument handling and
headless operation. An X11 rendering test does not qualify camera capture;
sensor/CSI/Argus errors remain separate from desktop-session selection.
