Shared FRAMOS Argus demo baseline -- NOT factory/production IQ tuning

For IMX678 this package deliberately reuses the byte-identical NITO accepted by the
previous Edge-AI FRAMOS IMX678 R39.2.0 setup on 2026-09-29. It is a generic ISP
migration baseline, not sensor/lens-specific FRAMOS calibration. Previous
capture, AE and AWB success does not qualify a new transport graph or image.
The R39.2.1 Yocto/ADI graph must be independently capture-tested.

Scope: Edge-AI Orin NX16G/P3767-0000, one DT-selected FRAMOS camera on
EDGEDES port 0: IMX678 3856x2180 or IMX676 3552x3556, RGGB12 at 10 FPS.
IMX676 has separately exported native mode data using the same generic template
and converter; neither profile is factory tuning. See ARGUS-DEMO-VALIDATION.txt
and IMX676-VALIDATION.txt in the layer for independent sensor results.
No other modes, HDR, cold-start reliability, factory color accuracy,
lens shading, or production use are qualified.

Integration and rollback:
The existing tegra-libraries-camera and tegra-argus-daemon recipes supply
proprietary runtime binaries; argus-samples and nvarguscamerasrc are built from
their existing source recipes. The demo never rebuilds proprietary Argus core.
The service drop-in uses an ExecCondition and a small shell launcher. The
helper's default auto policy selects one to four active homogeneous IMX678 or
IMX676 modules with
distinct imx678_port0_framos through imx678_port3_framos badges, or the
corresponding IMX676 badges. It sets the matching NVCAMERA_NITO_PATH and execs
the unchanged vendor daemon. Unsupported profiles and mixed profiles without
the modular marker skip the service.
One argus_camera, argus_oneshot and nvarguscamerasrc serve both sensors.
The service guard selects the DT profile, not a probed sensor silicon ID.
Each model-specific optional multi-port DTB uses boot-time GMSL link discovery and
omits absent module metadata from the live DT before Argus enumeration.
This requires the matching optional-link ADI and NVIDIA OOT driver patches;
it does not change either NITO or add hot-plug support.
New modular overlays permit explicit mixed-model device-tree composition.
EDGE_AI_ARGUS_NITO_SELECTION=auto uses a forced model-specific file for every
homogeneous connected subset, even in modular mixed-capable boot profiles.
It uses default-directory lookup without a global forced-file override only
when both models remain active and the modular DT marker is present.
Explicit single preserves homogeneous-only selection. Explicit per-camera
preserves marked-profile lookup even with one camera; unmarked legacy entries
retain their forced-file fallback. The selected forced file must be regular
and readable at both service condition and start. Inherited global selectors
are replaced or cleared, and effective policy/count/path are logged.
Automatic baseline NITO identity matching
is not qualified; file presence is not proof of correct data. Verify or
regenerate identities with official NVIDIA tools and qualify mixed capture.
The IMX678 extension retains the qualified native mode and existing port-0
source. New ports and simultaneous capture require separate hardware tests.
To restore generic Argus, remove the demo package/drop-in, reload systemd and
restart nvargus-daemon when no capture process is running. Existing legacy
NITO files and all driver/DTS/boot settings remain untouched by this package.
