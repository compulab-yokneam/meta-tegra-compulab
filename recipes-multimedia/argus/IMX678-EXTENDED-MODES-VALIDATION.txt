IMX678 native RAW12 mode extension -- 2026-10-15
================================================

Scope
-----
One FRAMOS IMX678 with FFA-GMSL-SER-V2A on EDGEDES ADI v18 physical port 0,
Edge-AI Orin NX16G, NVIDIA R39.2.1, Linux 6.18.48-yocto-standard-adi-v18.
Ports 1-3 were empty. This is a generic, uncalibrated ISP demo, not factory
IQ qualification or a simultaneous multi-camera bandwidth certification.

Implementation
--------------
NVIDIA OOT patch 0106 adds full-frame 30 FPS and two centered crop modes
from the FRAMOS reference windows. All modes use RGGB12, four sensor lanes
at 1188 Mb/s/lane, 37.125-MHz MCLK and HMAX 1100. Mode 0 retains the
existing register sequence and 10-FPS limits. New modes use VMAX 2250 and
maximum exposure 33212 microseconds. There is no RAW10, binning or HDR mode.
The mode count is clamped to the booted DT's mode count, retaining support
for old single-mode DTs. IMX676 is unchanged.

EDGE_AI_IMX678_EXTENDED_MODES defaults to "0". Setting it to "1" selects
both the four-mode DT definitions and the matching cumulative NITO source
in edge-ai-argus-framos-demo. The installed IMX678 NITO filename and the
model-selection helper are unchanged. The original NITO source is retained.
See files/PROVENANCE.txt for all input/tool hashes and generation commands.

NITO generation and runtime separation
--------------------------------------
The stock CONFIG migration path exports the provider's initial mode 0
before the requested nonzero mode is selected. These identical mode-0
dumps were rejected as inputs for modes 1-3.

Fresh selected-mode exports used NVIDIA's official migration hotfix
libnvscf.so through process-local LD_LIBRARY_PATH in an isolated CONFIG
daemon. Each mode captured a JPEG and exported its own 383108-byte CFG.
The hotfix installer was not run; installed NVIDIA core libraries were
never overwritten. No hotfix library or converter is included in the image.

The official converter loaded the generic template, then incorporated the
four fresh CFG files cumulatively at knobset IDs 0, 1, 2 and 3. All four
conversions validated UUID/schema/dataSize. Independently reapplying each
CFG to its own knobset in the completed file produced a byte-identical
output. The historical source profile caused an opaque converter abort;
it was preserved, not binary-patched. The extended file regenerates mode 0
from its fresh CFG; it is not byte-preserved historical tuning.

All following capture/preview/recording checks used the stock libnvscf.so:

The daemon's /proc maps confirmed /usr/lib/libnvscf.so, not the private
migration copy. Its diagnostics confirmed all four native mode geometries,
RAW12 Bayer input/output and exact mode-to-knobset mappings 0->0 through
3->3. The template's unused generic entry was not selected for these modes.

Limitations
-----------
These are single-camera functional checks, not factory color calibration.
AE/AWB convergence metadata, lens shading, HDR, cold-power cycles, mixed
sensors, other physical ports and simultaneous streams require additional
qualification. Crops reduce field of view; they are not full-field scaling.
Four full-resolution RAW12 30-FPS streams exceed the shared four-lane
2.5-Gb/s/lane output's payload budget. Keep mode 0 as the conservative
multi-camera default. Do not infer unsupported rates from recording caps.
